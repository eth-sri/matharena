# harness-wrapper

`harness-wrapper` presents Claude Code, Codex CLI, Kimi Code, Grok Build, Antigravity CLI,
Qwen Code, OpenCode, Deep Code, and Mistral Vibe through one Python interface. It keeps normalized JSONL
traces and session metadata inside the repository where an agent runs, supports
resumable/interruption-aware subprocesses, explicit API or OAuth model
configuration, and an optional Podman sandbox.

## Install

```console
uv pip install ./harness_wrapper
harness-wrapper install-clis
harness-wrapper login  %for oauth clients
```

`install-clis` resolves each CLI's current `latest` release and downloads its
versioned package into `~/.harness-wrapper`. Exact versions can be selected for
reproducible runs, for example:

```console
harness-wrapper install-clis kimi-code --version kimi-code=0.36.0
```

MathArena's harness solver does this automatically. Set `harness_version` in a
model config to an exact version, or omit it to use `latest`; the resolved
binary is cached by exact version on the host and mounted read-only into the
isolated runtime image.

## Quickstart

```python
from harness_wrapper import Agent, Model

model = Model(
    model="meta-llama/Llama-3.2-1B-Instruct",
    api_url="http://127.0.0.1:8000/v1",
    api_key="local-test-key",
    reasoning="high",
)
agent = Agent(model=model, dir=".", type="codex-cli")
events = agent.run("Reply with OK")
agent.resume("Now explain why", session_id=agent.session_id)
# Select a cached session without starting an empty model turn.
agent.resume(session_id=agent.session_id)
```

`reasoning` is optional and works with both explicit API credentials and OAuth
where the selected harness supports those modes. MathArena additionally
translates its model sampling and reasoning fields into the request generated by
the selected API-credit harness.

Every CLI runs in **YOLO** mode. Use a `Sandbox` if you need.

## Default behaviors

The idea is to be easy to use and mostly non-interactive. The only interactive path is oauth login/refresh.

The defaults are intended for unattended evaluation runs while preserving an
interactive login path when credentials need user action.

| Behavior | Default | Override |
| --- | --- | --- |
| Agent root | Current directory | `dir=...` or `root_dir=...` |
| OS sandbox | Disabled | `env=PodmanSandbox(...)` |
| Podman network | Enabled | `network_enabled=False` |
| CLI permissions | Native unrestricted mode | Supply an isolated `env`; adapter flags are fixed |
| OAuth login on model creation | Enabled | `OAuthConfig(auto_login=False)` |
| OAuth re-login after expiry/401 | Enabled | `OAuthConfig(auto_relogin=False)` |
| OAuth expiry safety window | 30 seconds | Set `config.expiry_leeway=SECONDS` |
| Rate-limit wait/retry | Enabled | `Agent(auto_wait=False)` |
| API fallback before waiting | Enabled | `Agent(auto_fallback=False)` |
| Rate-limit wait timeout | No deadline | `Agent(rate_limit_timeout=SECONDS)` |
| Poll interval while waiting | 30 seconds | `Agent(rate_limit_poll_interval=SECONDS)` |
| Runtime recovery attempts | 10 | `Agent(max_recovery_attempts=N)`; `0` disables retries |
| Subagents for OAuth | Auto-discovered | `subagents={...}` or `{}` to disable |
| Minimal CLI context | Disabled | `Agent(minimal_context=True)` |
| Version validation | Disabled | `validate_version=True` |
| API URL/key lookup from environment | Never | Pass explicit model arguments only |
| Library logs | Loguru's active sinks/level | Configure `loguru.logger` before constructing models |

`environment={...}` adds or replaces variables for one agent. It does not make
the model layer read API credentials from the environment.

`minimal_context=True` replaces the native system prompt with a short fixed
instruction and removes optional context through each CLI's supported settings
and invocation flags. Codex ignores user configuration and exec-policy rules
while retaining the local Code Mode executor required by code-mode-only models;
Claude uses safe mode; Kimi uses an explicit minimal agent file and an empty
skills directory; Antigravity uses a fresh private home and a custom agent limited
to file, search, and shell tools inside MathArena's Docker sandbox, with empty
skill/plugin/MCP dependencies and disabled slash expansion; Qwen uses `--safe-mode` plus `--bare` and excludes
web/delegation tools; OpenCode uses `--pure` with an inline provider-only config
and disables project instructions, plugins, MCP, LSP, formatters, subagents,
skills, and web tools. Deep Code uses native `--exec` with a private home, disabled
bundled/discovered skills and telemetry, denied network/MCP permissions, and a
proxy-enforced local-tool allowlist. Its saved JSONL supplies tool events and
resumable session IDs. Mistral Vibe uses a private `VIBE_HOME` with telemetry, connectors,
project context, and titles off; the proxy replaces its system prompt and allows only
`bash`, `read_file`, `write_file`, `edit`, and `todo`. Native authentication and resumable sessions continue to
work. Antigravity's closed client still adds built-in messaging/artifact and
current-time context; its separate title request is included in captured token
usage.

Antigravity auto-approves CLI tool permissions when running in an enabled
container sandbox (`--dangerously-skip-permissions`); host execution retains
permission checks. Container network, mount, and read-only-root restrictions
remain the isolation boundary. A zero exit code is not sufficient completion:
the adapter requires a final answer, recovers missing stream tails from the
terminal response in the native session database when available, and otherwise
resumes the same session within `max_recovery_attempts`. Exhausted recovery
raises an error; MathArena does not count an answerless attempt as a saved run.
The native SQLite/protobuf reader targets the CLI 1.1.x response schema and
rejects unknown layouts rather than extracting answers from reasoning text.

When a CLI uses the model proxy, every final post-override JSON request body is
persisted under `<agent-root>/.harness_wrapper/model_requests.jsonl`. Records include
the upstream path and payload but never HTTP headers, so provider credentials supplied
by the proxy are not written to this log. The file accumulates requests for the
whole workspace/session; its size is not the size of one API request. Repeated
conversation history and encrypted reasoning can make this cumulative log large.

## Agent lifecycle

`run(message)` starts a new native session. `resume(message, session_id=...)`
resumes a specific one; omit the ID to use the last repo-local cached session.
Calling `resume(session_id=...)` without a message only selects that session and
does not start an empty model turn.

`interrupt()` sends `SIGINT` to the active turn and returns whether a process was
running. `terminate()` requests process termination. Both are safe no-ops when
idle. `last_activity_at`, `seconds_since_activity()`, and `idle_for()` expose
activity timestamps suitable for external timeout/watchdog code. `dir` and
`root_dir` select the agent working tree; `root_dir` takes precedence if both
are provided.

`get_tokens()` returns a `TokenUsage` snapshot for the current native session.
It accumulates usage across resumes of that session and resets when `run()`
starts a fresh one:

```python
usage = agent.get_tokens()
print(
    usage.input_tokens,
    usage.output_tokens,
    usage.cache_read_tokens,
    usage.cache_write_tokens,
)
```

Cache values remain zero when the CLI does not report them. Anthropic cache
creation is exposed as `cache_write_tokens`; OpenAI-compatible cached input is
exposed as `cache_read_tokens`.

Gemini and OpenAI-compatible streaming usage snapshots are counted once per
response, using the last reported snapshot. Shared usage accounting includes
reasoning omitted from an output field by taking the larger of reported output
and `total_tokens - input_tokens` (or `prompt_tokens`). This covers Qwen's native
usage and Kimi/DeepCode's captured provider usage without adding reasoning twice
when output already includes it. OpenCode's separate `output` and `reasoning`
counts are added; Antigravity adds Gemini's candidate and thought counts. Codex,
Claude Code, and Muse use output totals that already include reasoning.
Kimi's provider usage records are saved in the trace for auditing; its native wire
alone may omit reasoning counts.

The August Gemini Kimi results repaired on 2026-09-11 store
`token_usage_recovery` in each run's `detailed_costs`. Input, cache, and visible
output come from native usage records; missing reasoning is estimated from each
request's API time, excluding tool execution. The fitted output rate and request
overhead are stored with the estimate, calibrated on 337 corrected OpenCode/Qwen
runs. Each estimate is bounded by visible output and the request's output limit.
The metadata also records requests without final usage. The output viewer labels
these output totals and costs as estimated; answers and judgments are unchanged.

Model proxy requests default to an 8-hour socket timeout. Codex uses an 8-hour
stream idle timeout; Claude API requests and Qwen stream guards also use 8 hours.
Claude's separate Bun socket-idle timer is disabled with
`BUN_CONFIG_HTTP_IDLE_TIMEOUT=0`, so non-streaming fallback requests obey the
8-hour API timeout instead of disconnecting after roughly six idle minutes.
If Codex reports an error, a warning that token counts and cost may omit usage
from interrupted requests is saved in the existing trace and MathArena run
history. Token counts remain those reported by the CLI.
Premature upstream EOFs are logged as warnings; any buffered bytes are forwarded
before closing the stream and leaving retries to the CLI.

The Codex adapter still runs the native `codex exec` process. Its subscription
bridge now connects to OpenAI at `wss://chatgpt.com/backend-api/codex/responses`,
using WebSockets rather than a long-lived HTTP streaming request. This is the
default; no model configuration or command-line flag is needed. The protected
local connection between the CLI and bridge continues to use SSE. The bridge
translates `response.create` requests and forwards each response event immediately,
including completion, failure, and usage. It preserves session/turn headers,
keeps credentials on the host, captures the actual WebSocket request, and enforces
tool restrictions before sending it. There is no upstream HTTP fallback.

This change addresses the transport difference from MathArena's older direct
`CodexCLISolver`: three active HTTP requests for P5, P6, and P10 disconnected
roughly 901 seconds after starting, despite receiving reasoning events about
11 seconds before the disconnect. That timing indicates a request-lifetime limit
on the upstream HTTP path rather than an idle timeout. A short live WebSocket
request and local transport tests passed; a long live evaluation is still needed
to confirm that these runs clear the 15-minute cutoff. WebSocket connect, receive,
and ping timeouts are eight hours; upstream service limits remain outside the
wrapper's control. Native CLI retries and the saved incomplete-usage warning remain
in place. Other providers retain their existing transports.

Every adapter normalizes messages, reasoning, tool calls/results, session IDs,
usage, errors, and recovery notices to `AgentEvent`. `stream()` and
`stream_resume()` yield events as they arrive; `run()` and `resume()` collect
the same events into lists.

Pass `oauth="openai"`, `oauth="anthropic"`, or `oauth="kimi"` instead of API
settings for plan-backed CLI authentication. OAuth state belongs to
`~/.harness-wrapper/auth.json`; conversation traces and the wrapper session
index belong to `.harness_wrapper/` under the invocation root.
After a native CLI login, harness-wrapper imports the provider's access token,
refresh token, expiry, and required account metadata into that single central
`auth.json`. The file and its parent directory are restricted to modes `0600`
and `0700`, respectively.

Discover and authenticate plan providers from the command line:

```console
harness-wrapper login --list
harness-wrapper login openai
harness-wrapper login anthropic
harness-wrapper login kimi
```

Running `harness-wrapper login` in a terminal offers an interactive selection;
add `--force` to replace an existing CLI-managed login. OpenAI uses Codex's
device-authorization flow by default, so it works over SSH: open the displayed
verification URL on your local computer and enter its code. On a desktop, pass
`--local-callback` to use the localhost browser callback instead.

`Model(..., oauth=...)` also logs in immediately by default when no usable
credential exists. To construct a model without prompting, retain the provider
adapter but disable its login policy:

```python
from harness_wrapper import Model
from harness_wrapper.models.oauth import (
    anthropic_oauth_config,
    kimi_oauth_config,
    openai_oauth_config,
)

config = openai_oauth_config(
    device_auth=True,
    auto_login=False,
    auto_relogin=False,
)
model = Model("gpt-model", oauth="openai", oauth_config=config)
```

The equivalent provider builders accept `auto_login` and `auto_relogin` for
Claude and Kimi. OpenAI additionally accepts `device_auth`; the programmatic
builder defaults to Codex's local callback, while the `harness-wrapper login`
command defaults to device authorization. A custom `OAuthConfig` can replace
login, credential loading/refresh, status, model discovery, and rate-limit
hooks for another deployment.

OpenAI OAuth also works with the Kimi adapter. The wrapper starts a protected
Responses bridge for that invocation, gives
Kimi a random one-time bridge key, and keeps the real Codex OAuth token out of
Kimi's arguments, environment, and configuration. Sandboxed invocations reach
the bridge through the sandbox's host-service route.

All three built-in OAuth providers poll their native subscription limits:
OpenAI uses Codex app-server's `account/rateLimits/read`, while Claude and Kimi
read their plan usage endpoints with the imported OAuth token. Results are
normalized to 0–1 utilization values and Unix reset timestamps:

```python
snapshot = model.poll_rate_limits()
for limit in snapshot.limits:
    print(limit.name, limit.utilization, limit.resets_at, limit.limited)

# Poll until every exhausted window resets, then return a fresh snapshot.
snapshot = model.auto_wait(timeout=6 * 60 * 60)
```

`auto_wait()` sleeps until the next reported reset, capped at one hour so it
still notices early capacity changes. Pass `poll_interval=` to change that
safety-poll interval.

Normal `Agent.run()` and `Agent.resume()` calls perform this coordination
automatically. Before every turn the wrapper rechecks OAuth status and plan
capacity. During a turn it recognizes native 401/authentication and 429/usage
limit failures. Authentication failures run the interactive provider login and
resume the same native session. Rate-limit failures select the next compatible
configured API fallback; if none is available, polling continues until capacity
returns and the session resumes. Recovery events are emitted as `AgentEvent`
objects with type `"recovery"`.

All harness invocation failures use `max_recovery_attempts` (default: ten additional
attempts without an intervening successful model request). This includes nonzero exits,
explicit CLI error events even with exit code 0,
startup/authentication exceptions, and unknown errors; no error-message allowlist is
required. A completed model request observed by the API proxy resets the allowance,
even if the same CLI invocation later fails. Partial streams, usage snapshots, replayed
native transcript events, and token-limited completions do not reset it. The recovery
event's `attempt` counts retries since the last observed successful request.
Every wrapper retry waits 60 seconds, including authentication/quota recovery,
model fallback, incomplete responses, and output-limit continuations. A known session is resumed; otherwise the wrapper
resumes the latest session if progress was emitted, or repeats the original prompt if
nothing started. A failed resume is retried without starting a fresh task. Optional
reauthentication, quota waits, and configured fallbacks remain recovery actions, and
failure of one of those actions does not disable retries. Cancellation and competition
budgets stop retries. Tool failures remain feedback for the running model rather than
triggering wrapper retries. Explicit successful empty completions are still saved.
Qwen's `[API Error: ...]` terminal answers and missing/truncated terminal results are
failures even when the CLI reports success; reported usage is retained across retries.
Set `max_recovery_attempts=0` to disable wrapper retries. Native CLI/request retries
can happen inside each invocation and have their own limits.

Claude Code output-limit failures also resume the saved native session within
`max_recovery_attempts` (default 10). A terminal `stop_reason: "max_tokens"`
also triggers continuation when the CLI reports `is_error: false` and exits 0.
The wrapper captures terminal usage before resuming. Ordinary `end_turn` results,
including empty answers, do not trigger output-limit recovery.
When output-limit recovery is exhausted, Claude
emits an empty result with `reason: max_output_tokens`, preserving usage and partial
work. MathArena saves it as a finished attempt, as it does for Muse's exhausted
continuation. Connection and other provider failures still follow the error path.
Each resumed CLI invocation has its own internal retry budget: Claude Code 2.1.267 allows an initial request plus three
output-limit continuations, so ten wrapper resumptions allow up to 44 attempts
for repeated truncation. Failed attempts retain their token usage, and recoveries
emit `output_limit_resume`. This cannot restore thinking omitted by the CLI.

Temporary server overload (`Selected model is at capacity`, `server_overloaded`,
or `server_is_overloaded`) retries the same model with the same 60-second delay. It resumes the existing session, preserves authentication and model
settings, and never selects an API/model fallback or polls subscription quota for
this error. Set `max_recovery_attempts=0` to disable these retries. This follows
[OpenAI's overload guidance](https://developers.openai.com/api/docs/guides/error-codes).

```python
from harness_wrapper import Agent, Model

api_backup = Model(
    "backup-model",
    api_url="https://gateway.example/v1",
    api_key="explicit-key",
)
plan = Model("plan-model", oauth="openai", fallbacks=[api_backup])

agent = Agent(
    type="codex",
    model=plan,
    dir=".",
    auto_fallback=True,  # use api_backup before waiting
    auto_wait=True,  # wait when no fallback remains
    rate_limit_timeout=None,  # no deadline
    rate_limit_poll_interval=30,
    max_recovery_attempts=10,
)
```

Fallbacks are tried in declaration order and must support a protocol accepted
by the selected harness. Set `auto_fallback=False` to keep the OAuth model even
when a backup was configured. Set `auto_wait=False` to surface a rate-limit
failure immediately. Set `OAuthConfig(auto_relogin=False)` through a provider
builder to surface expired/rejected credentials instead of launching login.

For example, a rate-limited Kimi plan can switch automatically to a Bifrost
OpenRouter model:

```python
from harness_wrapper import Agent, Model

bifrost = Model(
    "openrouter/moonshotai/kimi-k3",
    api_url="https://srlx.inf.ethz.ch/v1",
    api_key=explicit_bifrost_key,
    headers={"x-bf-vk": explicit_bifrost_key},
)
kimi_plan = Model("kimi-code/k3", oauth="kimi", fallbacks=[bifrost])
agent = Agent(type="kimi", model=kimi_plan, auto_fallback=True)
```

OAuth access/refresh tokens and account metadata are mirrored into
`~/.harness-wrapper/auth.json`. Writes are atomic; the directory and file use
permissions `0700` and `0600`. Provider CLIs may retain their own native login
files because they own the authorization and refresh protocols; the wrapper's
central file is the only credential file created directly by this library and
is resynchronized after login or native token rotation.

## Logging

Authentication, native credential import and refresh, rate-limit polling,
capacity waits, interactive re-login, fallback selection, CLI retry/resume,
and the OpenAI OAuth bridge emit structured Loguru records. Records bind safe
context such as `component`, `provider`, `harness`, `model`, `session_id`, and
recovery reason. Prompts, responses, access/refresh tokens, API keys, request
headers, and process environments are never logged.

The library uses the application's existing Loguru configuration and does not
replace or remove sinks. To override the destination or level:

```python
import sys
from loguru import logger

logger.remove()
logger.add(sys.stderr, level="INFO", serialize=True)
```

Use `level="WARNING"` for only waits, fallback/recovery decisions, and failures,
or `level="DEBUG"` for credential synchronization and provider polling detail.

## Explicit API models and compatibility

API credentials are constructor data and are never sourced from `OPENAI_*`,
`ANTHROPIC_*`, or similar process variables. A single model can expose one or
both wire protocols:

```python
from harness_wrapper import APIEndpoint, APIType, Model

model = Model(
    "served-model",
    endpoints=[
        APIEndpoint(APIType.OPENAI, "https://gateway.example/v1", "openai-key"),
        APIEndpoint(APIType.ANTHROPIC, "https://gateway.example", "anthropic-key"),
    ],
)

print(model.supported_endpoints())  # frozenset({'openai', 'anthropic'})
print(model.supported_api_types())  # typed APIType values
print(model.endpoint_for("openai").url)  # configured location
```

For one endpoint, use `api_url`, `api_key`, and optional `api_type` (default:
`"openai"`). `headers={...}` adds explicit custom headers. API and OAuth
arguments are mutually exclusive. Claude Code accepts Anthropic-compatible
models, Codex, OpenCode, Deep Code, and Mistral Vibe accept OpenAI-compatible models, Kimi and Qwen accept
either, and Antigravity CLI uses the native Gemini API. Model construction reports a
descriptive compatibility error before starting a CLI. Claude-plan OAuth is
restricted to Claude Code, Kimi-plan OAuth to Kimi Code, and OpenAI-plan OAuth
to Codex or local Kimi through the bridge described above. The isolated
MathArena adapters currently restrict Antigravity CLI, Qwen Code, OpenCode, Deep Code, and Mistral Vibe to
explicit API-credit auth; this avoids silently importing account state from a
developer machine.

For OpenRouter endpoints, `openrouter_providers=("z-ai", "together")` restricts
requests to those provider slugs. Provider restrictions are injected by the
invocation-local proxy, which also works through a sandbox's host-service route,
including an offline `PodmanSandbox`.

Gateways such as SRI Bifrost use the same explicit API model with their required
custom headers:

```python
model = Model(
    "served-model",
    api_url="https://gateway.example/v1",
    api_key="explicit-key",
    headers={"x-bf-vk": "explicit-key"},
)
```

The inference URL, key, and headers remain explicit and are never inferred from
`secret.sh` or environment variables. When Kimi uses a model with custom

## Subagents

`Agent` accepts a `subagents` mapping whose keys are names visible to the parent
agent and whose values are model objects or model IDs:

```python
from harness_wrapper import Agent, Model

primary = Model(
    "large-model",
    api_url="https://models.example/v1",
    api_key="secret",
)
fast = Model(
    "fast-model",
    api_url="https://models.example/v1",
    api_key="secret",
)

agent = Agent(
    type="codex",
    model=primary,
    subagents={"fast-worker": fast},
    dir=".",
)
agent.run("Ask fast-worker to inspect the test failures, then fix them.")
```

Names must begin with a letter and contain at most 64 letters, digits, hyphens,
or underscores. Each entry becomes a portable definition containing the name,
model ID, a delegation description, and a subagent prompt. The parent model is
made aware of the choices through the selected CLI's native mechanism:

- Claude receives definitions through `--agents`.
- Codex enables `multi_agent` and receives `agents.<name>` configuration.
- Kimi enables its v2 `Agent` and `AgentSwarm` tools. Kimi chooses between the
  primary model and one configured secondary model rather than arbitrary named
  model definitions.

The native harness decides when to delegate based on the user request, current
context, and each definition's description. Mention a subagent name in the
request when a particular worker must be used. Subagent events remain part of
the native CLI stream and are recorded in the wrapper's normal trace.

### Automatic OAuth subagents

When `subagents` is omitted and the primary model uses OAuth, harness-wrapper
discovers the models available through the authenticated plan and advertises
them automatically:

- Codex reads the account-aware catalog returned by `codex debug models` and
  ignores hidden internal entries.
- Claude advertises the entitlement-aware `fable`, `opus`, `sonnet`, and
  `haiku` aliases. Claude Code resolves each alias against the subscription and
  organization model policy when the subagent starts.
- Kimi reads model entries backed by OAuth providers from
  `kimi provider list --json`.

Generated names use the `model-<normalized-model-id>` form. For example,
`vendor/model.v2` becomes `model-vendor-model-v2`. Inspect the effective names
and model IDs before issuing a task:

```python
model = Model("gpt-5.6-sol", oauth="openai")
agent = Agent(model=model, dir=".", type="codex")

print(agent.subagents)
print(agent.available_subagent_models())
```

Discovery results are cached on the OAuth model object. Call
`model.available_models(refresh=True)` and create a new `Agent` to refresh the
catalog after an account or organization policy change. If discovery is not
supported by an older CLI, the selected primary model is still advertised as a
subagent instead of preventing the agent from starting.

Pass an explicit mapping to replace the automatic catalog. Pass an empty
mapping to disable subagents entirely:

```python
no_delegation = Agent(
    type="claude",
    model=Model("sonnet", oauth="anthropic"),
    subagents={},
    dir=".",
)
```

### Kimi model limitation

Kimi currently supports a primary model and one secondary model per invocation.
For native Kimi OAuth, harness-wrapper selects the first discovered model that
differs from the primary and exposes it as Kimi's secondary. Other discovered
models remain inspectable through `available_subagent_models()`, but Kimi cannot
select them for that invocation.

When Kimi runs through the OpenAI OAuth loopback bridge, its subagents inherit
the primary OpenAI model; a different catalog entry cannot be configured as
Kimi's secondary. This restriction belongs to Kimi's native subagent interface,
not to OAuth discovery.

## Traces

The harness records all traces in `.harness_wrapper/traces` and the last 100
session IDs per harness in `.harness_wrapper/sessions.json` under the agent
root. Trace writes use a universal JSONL schema and include original user
messages, system/developer prompts captured from local model requests, normalized
answers, reasoning, tool calls/results, usage/cost fields when supplied by the
CLI, session metadata, raw native events, errors, and OAuth recovery events.
Normal appends retain the parsed history in memory and check file identity,
size, and modification metadata instead of reparsing old records. Initial loads
and detected file changes use full validation so concurrent writers and crash
recovery remain supported. File locking and durable writes also remain enabled.
Visible thinking is stored as `reasoning` events. Provider state that must be
replayed unchanged—such as OpenAI Responses `encrypted_content` and Anthropic
signed or `redacted_thinking` blocks—is stored as `reasoning_encrypted` with the
complete original block. The latter is intentionally opaque but can be passed
back to the same provider/model. Treat trace files as sensitive: their local
permissions are restricted to the current user, but they now contain model
reasoning state in addition to prompts and answers.
Request capture uses an invocation-local protected proxy for API and OAuth
models. Sandboxes expose that proxy through their `expose_host_service()` route;
authorization headers are forwarded in memory and are never added to the trace.
Pass a custom `Trace`-compatible object through `Agent(trace=...)` to redirect or
integrate storage.

Render a trace as a self-contained, dependency-free HTML timeline:

```python
from pathlib import Path

from harness_wrapper import Trace, render_trace_html

trace = Trace.load(".harness_wrapper/traces/session.jsonl")
Path("trace.html").write_text(render_trace_html(trace), encoding="utf-8")
```

## Sandboxing

```python
from pathlib import Path

from harness_wrapper import PodmanSandbox, SandboxMount

cli_bin = Path("~/.harness-wrapper/clis/native/bin").expanduser()
sandbox = PodmanSandbox(
    root=".",
    image="python:3.12-slim",
    network_enabled=False,
    container_executable="/opt/harness-wrapper-clis/codex",
    mounts=[
        # This stable directory contains real binaries, not npm symlinks.
        SandboxMount(cli_bin, "/opt/harness-wrapper-clis", writable=False),
        SandboxMount("/data/read-only", "/data", writable=False),
    ],
)
```

`Sandbox`/`LocalSandbox` are intentionally ordinary local command runners, not
security boundaries. `PodmanSandbox` creates an ephemeral container per command
and only mounts paths that were configured explicitly. The agent root is mounted
read/write at `/workspace` by default; additional mounts are read-only unless
`writable=True`. Network access defaults to Podman's bridge network and can be
disabled with `network_enabled=False`. Change the image, container root, Podman
binary, or low-level arguments with `image`, `container_root`,
`podman_executable`, and `extra_args`.

`container_executable` can be an absolute container path or a command found on
the container's `PATH`. It replaces absolute host executable paths; relative
helper commands such as `./check.sh` remain unchanged.

During an agent invocation, `network_enabled=False` still permits the protected
model proxy through a temporary internal Podman network. The container has no
direct external route; the host-side proxy performs the upstream request and the
temporary network is removed when the invocation finishes.

For offline sandboxes, all built-in harness adapters also enforce an offline
policy at their host-side model proxy, including the Codex OAuth WebSocket and
Kimi custom-header bridges. Requests are limited to the configured model (plus
the pinned Antigravity CLI's existing Flash Lite housekeeping model) and to
inference, compaction, token-counting and model-catalog endpoints. The proxy
rejects provider-hosted tools, web plugins and remote URL inputs; local function
tools, inline data and compaction remain available. Policy violations return
`403 offline_policy_violation` without reaching the provider. Malformed request
bodies fail closed, and the HTTP proxies do not follow upstream redirects.
This follows `network_enabled=False` (MathArena's `direct_network: false`); no
additional competition setting is needed. The CLI's local proxy secret alone
does not enforce this boundary, because shell tools can inspect the CLI's own
configuration. Already-running processes must be restarted to load this policy.

Both local and Podman environments expose `run(...)`, `copy_in(...)`,
`copy_out(...)`, and `delete(...)`. Filesystem helpers constrain managed paths
to the configured root, reject symlink traversal, and never delete the root
itself:

```python
result = sandbox.run(["python", "-V"], timeout=30, check=True)
sandbox.copy_in("fixtures/input.json", "work/input.json")
sandbox.copy_out("work/result.json", "./result.json")
sandbox.delete("work", missing_ok=True)
```

Mounting the stable
native bin directory as above makes every supported CLI available without a
host-specific executable mount path. Set `container_executable` to the selected
CLI's path in that mount (`claude`, `codex`, or `kimi`).

Native provider OAuth requires that the corresponding CLI credential files be
made available deliberately. Explicit API models remain the simplest mode for
hermetic container evaluations.

## Extending harness-wrapper

`Agent` and `AbstractModel` are public extension points. A new CLI adapter
subclasses `Agent`, declares `harness_name`, aliases, accepted API types, pinned
installation metadata, implements `build_command()`, and optionally overrides
`normalize_event()`. Registration happens through `Agent.__init_subclass__`, so
the factory can resolve the declared names without changing its constructor.

A model implementation supplies `supported_endpoints()`,
`supported_api_types()`, `assert_compatible()`, and `model_for()`. OAuth
providers can reuse `OAuthModel` with an `OAuthConfig`; explicit protocols can
reuse `APIModel` and `APIEndpoint`. Sandbox subclasses normally only need to
override `prepare_command()`. This keeps CLI, model, tracing, and execution
environment concerns independent.

## Muse Code

`Agent(type="muse", ...)` runs Meta's native `muse exec --json`, with aliases
`muse-code` and `muse-cli`. Install it using `harness-wrapper install-clis muse-code`
(or `--version muse-code=1.0.3-R2198.1`). The installer verifies Meta's release
checksum and supports versioned read-only container mounts. API auth uses the
existing Responses request proxy; completion usage includes reasoning tokens.
The adapter records tool calls/results and requires an explicit native completion.
MathArena saves explicitly completed empty answers without a final-answer reprompt
for every harness. Lean runs still check and submit `Solution.lean` from the workspace.
Muse's first-model-event and stream-idle timeouts are both set to eight hours
(`TBH_STREAM_FIRST_EVENT_TIMEOUT_SECS` and `TBH_STREAM_IDLE_TIMEOUT_SECS`),
so lengthy reasoning does not trigger its default three-minute first-event retry.
Compaction preserves the internal `generate_summary` schema and native summary settings;
solver request overrides apply to solving turns. Summary tokens still count toward usage.
Meta `server_error` failures inside an HTTP-200 response stream retry the exact
HTTP request in the same native turn, up to `max_recovery_attempts` additional
requests (default: three), with a 60-second delay before every retry. Meta also uses a generic HTTP 400 `invalid_request_error` when the input plus
reserved output exceeds its context window. For that exact generic error, the
adapter halves `max_output_tokens`, waits 60 seconds, and retries the same conversation, bounded by
`max_recovery_attempts`. It retains the reduced allowance on subsequent solver
requests; reasoning effort, input (including encrypted reasoning), tools, and
compaction settings remain intact. The warning, adjustment event, and actual
retried request are recorded. Persistent errors still fail and leave the attempt
pending. Other HTTP failures retain Muse's existing retry handling. No user message is inserted for request retries. Failed
responses retain reported usage, but their partial text/tool calls are withheld
from Muse. To make this possible, SSE bodies are spooled before delivery (over
1 MiB spills to a temporary file); native progress appears when the response
finishes. Other harness transports retain immediate streaming.

A turn truncated by `max_output_tokens` resumes its native session within the shared
`max_recovery_attempts` budget (default: ten additional attempts), using an empty text input so Muse inserts its own
previous-turn placeholder without an extra model-visible user message. Solver
requests use the configured output ceiling (1,000,000 in MathArena's Muse Spark 1.3 config),
subject to the context-budget adjustment above. Once the shared retry budget is
exhausted, another token cutoff emits an empty result;
MathArena still uses `Solution.lean` for Lean submissions. `max_recovery_attempts=0`
disables the continuation; generation-error request retries keep their separate existing limit. Muse's internal request/tool
loop is unchanged: this caps wrapper continuations, not the whole conversation's
token total.

Continuations use `muse serve` and its `session/resume` / `turn/start` protocol. Muse
1.0.3's `exec --session-id` can restore an incorrect journal sequence after compaction
and fail with `non-monotonic sequence`. The session protocol avoids that path without
editing or reconstructing the journal. It loads the retained context (including native
compaction summaries), checks the session and model identity, and preserves the same
outer sandbox. The adapter fetches catalog metadata once per Agent when first resuming
and exposes only the configured model to the native host. Provider request overrides
still enforce the configured reasoning effort and output budget. Final-answer text
comes from the full provider response after native completion, since MSP view items
can truncate long text.

Resume a retained conversation with `agent.resume(prompt, session_id=...)`. Native
history reconstruction errors still fail explicitly; the adapter does not discard
history or silently restart when Muse cannot replay it.
See [MathArena setup](../readmes/README_harness.md#meta-muse-code) for model config,
Docker isolation, and the account's supported reasoning effort.


## Grok Build

`Agent(type="grok", ...)` runs the native Grok Build headless CLI (aliases:
`grok-build`, `grok-cli`). Install a pinned release with
`harness-wrapper install-clis grok-build --version grok-build=1.0.40`.
The installer uses the official versioned HTTPS binary and verifies `--version`;
xAI's installer does not publish a checksum manifest.

The adapter uses a private `GROK_HOME`, a custom Responses model, file-based
prompts, streaming JSON events, and native session resume. Set
`model_context_window` to control native compaction (default 500,000). API
credentials remain in proxy headers; the CLI receives a placeholder. Only API
credit authentication is supported. Model request overrides and request capture
use the same proxy as the other adapters. The Responses route is stateless:
Grok replays full history on tool continuations and resume, and the proxy enforces
`store: false` and rejects non-null `previous_response_id`.

A fixed output reservation can exceed the remaining context as tool history grows.
On an explicit context-overflow HTTP 400 with OpenRouter's text/tool input counts,
the adapter retries the same request once with `max_output_tokens` reduced to the
reported context size minus input minus 8,192 tokens of headroom. It retains the
lower ceiling for subsequent calls and adjusts again if required. The corrected
request and adjustment are logged; input, encrypted reasoning, and tools are
preserved. Streaming stays immediate, and other errors still reach the native CLI.
If the input itself leaves no room, the original error is forwarded unchanged.

Minimal mode removes optional context and filters tools to local terminal, file,
search, and todo operations. The title-only `session_title` schema remains intact.
The native sandbox is disabled because MathArena supplies the outer Docker
boundary. Using this adapter without a sandbox runs tools on the local machine,
like the other CLI adapters.

Usage comes from every provider response, including auxiliary calls and failed
requests with reported usage. Reasoning is already included in completion tokens;
native usage events are not added again. Explicit `end_turn` with no text is an
empty result, while missing or unsuccessful terminal events remain failures.
Grok Build retains its native inference retries, including retries for reasoning-only
provider responses; MathArena's wrapper retry budget applies to CLI invocation failures.

See [MathArena configuration](../readmes/README_harness.md#grok-47-through-openrouter-and-grok-build)
and the [official Grok Build reference](https://docs.x.ai/build/cli/reference).

## Mistral Vibe

`Agent(type="vibe", ...)` runs Mistral Vibe's programmatic mode (aliases: `mistral-vibe`,
`vibe-cli`, `mistral`). Install a pinned release with
`harness-wrapper install-clis mistral-vibe --version mistral-vibe=2.26.1`. The installer
downloads the standalone PyInstaller bundle from the GitHub release, verifies its SHA-256
digest, and installs `bin/vibe` with its adjacent `bin/_internal` runtime.

The adapter writes a private `$VIBE_HOME/config.toml` with one generic OpenAI-compatible
provider pointing at the request proxy, sends the prompt on stdin to `vibe -p`, parses
`--output streaming` history entries, and resumes with `--resume <id>` under
`VIBE_CLI=python`. Vibe prints no terminal event: a zero exit yields a result containing the
turn's last assistant text. Usage comes from proxied provider responses. Set
`model_context_window` to derive Vibe's compaction threshold from the proxy's `max_tokens`.
The proxy drops Vibe's built-in temperature unless the model's request overrides set one,
and withholds mid-stream `finish_reason: "error"` events so Vibe retries instead of
accepting a truncated completion. See
[MathArena configuration](../readmes/README_harness.md#mistral-large-4-through-mistral-vibe).


Minimal-context agents can use shell networking and native web tools when
`env.network_enabled=True`. MathArena Docker runs default to offline.
